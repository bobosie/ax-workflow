# AX Recall — 語意記憶查詢

在排查問題、做技術決策、或要斷言「有沒有做過 X」之前，**先查記憶不要盲試**。

## 執行

1. 用 `ax_recall` 查詢（**單向降級**：AX Server 主 → 本機 mem 備）：
   ```bash
   ax_recall "$ARGUMENTS" --top-k 5
   ```
   輸出第一行標明實際命中來源：
   - `[AX-SERVER bm25]` — 命中主檢索（BM25 bigram，實證 R@5≈57%，勝向量）。
   - `[LOCAL-FALLBACK mem/vector]` — AX Server 不可達，已**降級**到本機 mem 向量 KNN；結果照用，但知道現在是備援路徑（個人範圍、可能略舊）。
   - `[RECALL-UNAVAILABLE]` — 兩者皆不可用 → 用空上下文續行，並在回覆標記「本次無歷史記憶上下文」。
   > 備援是**單向**的：本機結果只在本地用，**永不回流 server**（守 scrub / PII 邊界）。若 `ax_recall` 不存在（未裝 server），退回 `memsearch search "$ARGUMENTS" --top-k 5`（需安裝 memsearch，見部署文件）。
2. 掃 top-5 結果，判斷相關度：
   - **完全相符** → 直接沿用過去解法，並說明出處（哪個 lesson / memory）。
   - **部分相符** → 以過去解法為基礎調整，寫明不同點。
   - **查無相符** → 才自創，並標注「首次遇到：<問題摘要>」供事後補 lessons。⚠️ 但 recall 命中率約 60%，**「查無」≠「沒做過」**（可能是知識庫 miss）；「查遍」＝top-5 ＋（涉本專案）掃 `doc/lessons-learned/` ＋ 最多換 1 次關鍵字，別無限 retry。
3. 若 recall 不可用或查無，不要卡住：改用空上下文繼續，並在回覆標記「本次無歷史記憶上下文」。

## 何時主動觸發（不只開場）
遇到錯誤訊息、工具行為詭異、要說「做不到 / 沒掛 / 沒有」、找不到工具/路徑/憑證、要對系統做假設或自創方案——**第一動作是 recall**。成本 3 秒，省掉 4-30 分鐘長路。
